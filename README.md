# DA3408 A4 — Monitoring a CPU-only Image Captioner with Prometheus & Grafana

A Streamlit app captions images on CPU with BLIP (`Salesforce/blip-image-captioning-base`) in **Single** mode (one image)
and **Bulk** mode (a ZIP of images). It is instrumented with `prometheus_client` (`/metrics` on a separate port), scraped by
Prometheus together with node_exporter (CPU / RAM / disk), and shown on a Grafana dashboard that follows the 7 Commandments
of Plotting. Alert rules and Alertmanager are included.

```
browser ─► Streamlit :8501 ── same process ──► /metrics :18000 ─┐
node_exporter :9100 (CPU / RAM / disk) ─────────────────────────┴─► Prometheus :9090 ─► Grafana :3000
                                                                       └─ rules.yml ─► Alertmanager :9093 ─► webhook :5001
```

## Setup (once)

Needs Linux, Python 3.10+ (tested on 3.14) in an activated virtual environment, about 3 GB of disk, and free ports 3000, 8501, 9090, 9093, 9100, 18000.

```bash
source <your-venv>/bin/activate
./run.sh setup              # CPU torch + requirements, downloads Prometheus, node_exporter, Alertmanager, Grafana and the model
python make_sample_zips.py  # creates sample_data/
```

## Run

```bash
./run.sh start              # node_exporter, Alertmanager, Prometheus, Grafana, Streamlit
./run.sh status             # ports and Prometheus targets
```
Open http://localhost:8501 once; the metrics server and the model start with the first browser session.

| Service | URL |
|---|---|
| App | http://localhost:8501 |
| App metrics | http://localhost:18000/metrics |
| node_exporter | http://localhost:9100/metrics |
| Prometheus targets / alerts | http://localhost:9090/targets , http://localhost:9090/alerts |
| Grafana dashboard (auto-loaded, no login) | http://localhost:3000 |

Upload `sample_data/cat.jpg` (Single) and `sample_data/bulk_60.zip` (Bulk) and watch the dashboard. `mixed.zip`, `corrupt.zip` and
`empty.zip` show that bad input is reported without crashing the app. To see alerts, run the listener from the top of
`alertmanager.yml` in a spare terminal. `./run.sh stop` stops everything; `./run.sh reset` also wipes metrics and Grafana state.

## Metrics (`metrics.py`, prefix `captioner_`)

| Type | Examples | Labels |
|---|---|---|
| Counter | `images_processed_total`, `requests_total`, `errors_total`, `caption_words_total`, `uploaded_bytes_total` | `mode` (single/bulk), `status`, `error_type` |
| Counter (client) | `client_images_total`, `client_requests_total` | `client_ip`, `session_id`, `browser` |
| Gauge | `active_requests`, `waiting_for_model`, `model_memory_bytes`, `process_memory_bytes`, `batch_progress_ratio`, `recent_sessions` | `mode` |
| Histogram | `inference_duration_seconds`, `request_duration_seconds`, `image_size_bytes`, `batch_images` | `mode` |
| Summary (`_sum`, `_count`) | `caption_length_chars`, `upload_size_bytes`, `client_inference_seconds` | `mode`, `client_ip` |
| Info | `build_info` | model, device, version |

The Python Summary exposes `_sum` and `_count` (no quantiles); `_total` comes from the Counters. `session_id` is cut to 8 characters
and `browser` to a handful of values, to keep label cardinality low.

## Dashboard (`dashboard.json`, refresh 5 s)

Top to bottom: **1 Health** (app and node_exporter up/down, alerts, model, active requests, error ratio) → **2 Application**
(throughput, p50/p95/p99 latency on a log axis, mean latency, errors, queue) → **3 Clients** (per-IP table, bar chart, browsers)
→ **4 System** (CPU, RAM, disk, load, network from node_exporter) → **5 Correlation** (an app metric on the left axis against a
hardware metric on the right axis). Import it elsewhere with *Dashboards → New → Import*.

Seven commandments: colour-blind-safe Okabe-Ito palette (UP/DOWN also written as text); series differ by line style and point size so
they survive greyscale print; every axis is named; axis labels state unit and scale (`linear` or `log`); legends on every plot; each
panel has a title with a subtitle; each row has a short story and each panel a description (the ⓘ icon).

## Query logic

Prometheus scrapes every 1 s, so `[15s]` windows hold 15 samples.

* `rate(counter[15s])` = (last − first value) / elapsed seconds. A counter going 100 → 130 in 15 s is 2 images/s.
* Mean latency = `rate(x_sum) / rate(x_count)`: seconds spent divided by images done in the same window.
* `histogram_quantile(0.95, sum by (le) (rate(bucket[1m])))`: buckets are cumulative. If ≤1 s holds 40 images, ≤2 s 90 and ≤3 s 100, the
  95th percentile is rank 95, inside (2, 3]: 2 + (3 − 2) × (95 − 90) / (100 − 90) = 2.5 s.
* CPU busy % = `100 × (1 − avg(rate(node_cpu_seconds_total{mode="idle"}[15s])))`. If each core is idle 0.25 s per second, it is 75 % busy.
* RAM used % = `100 × (1 − MemAvailable / MemTotal)`; disk used % = `100 × (1 − avail / size)`; load per core = `node_load1 / cores`.
* App CPU = `100 × rate(process_cpu_seconds_total[15s])`, in percent of one core (above 100 means several threads).
* Error ratio = errors/s ÷ (images/s > 0). The `> 0` removes the idle case; `or vector(0)` shows 0 instead of "No data".
